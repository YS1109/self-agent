# 1.0 可靠性切片（开发计划与接线约束）

本文件是分切片实施计划，不是发布完成声明。运行版本仍为 0.6.0；没有签名身份、生产更新源、安装发布或公网部署授权。三平台编译/CI、真实安装生命周期、OS 凭据授权和 GUI 点击须分别记录，不互相替代。

## 当前实现与独立模块

- `reliability/storage.rs`：SQLite 一致快照、版本 ledger、备份检查、离线恢复与中断恢复。已接入真实 Store、owner HTTP、CLI；原始独立模块审查已通过，应用接线需独立复审。
- `reliability/diagnostics.rs`、`update.rs`：固定字段诊断及签名清单/产物校验、私有暂存。13 项独立测试通过；生产更新明确禁用，尚无安装器或持久降级下限；update 源码待后续独立提交，不混入首个存储切片。
- `reliability/jobs.rs`：在线备份持久意图/回执、一次领取与重启不重放，9 项隔离 SQLite 测试通过，已接 owner HTTP 与独立工作线程，断连后只读恢复原回执。
- 生命周期/协议 helper 21 项隔离测试通过（包含已提交意图但尚未登记 worker 的取消/panic）；需再接入后台、CLI 和桌面。独立 helper 不能视为实际进程生命周期验收。

## 第一应用切片：存储、诊断与离线恢复

1. 数据目录锁在任何 Store 打开前取得；先处理已存在的恢复 journal，再用只读连接检查兼容性，之后才允许读写打开、事务迁移及正常恢复。较新/不一致版本不得自动重建数据库。只读检查不进行应用迁移写入；SQLite WAL 的共享内存协调不等于所有 sidecar 字节都不可变。
2. 所有当前建表/ALTER/旧事件迁移纳入同一 ledger 事务。后续 QQ / H5 新 schema 必须增加显式版本，不绕过 ledger。已有版本0数据库、旧会话、配置和任务历史用真实 Store 回归验证。
3. 在线备份使用 SQLite backup API，不拷贝活跃 WAL 文件对。备份是私有历史，不是脱敏诊断；显式所有者选择目的目录，新建、不覆盖，单数据库影像上限128 MiB，取消/超时不发布完整 bundle。
4. 恢复仅离线执行；同 daemon.lock 防止活跃后台被替换。显式核对所有者提供的 SHA-256（校验损坏，不认证来源），检查完整性/结构、迁移及业务记录后才替换。错标记/材料不一致保留原物并阻断；中断恢复不得把别的目录快照写入原目录。
5. 恢复终止旧执行器、批准与排队工作；摘要/thread关联失效。命名服务/MCP禁用并解除引用，恢复审计不具备真实 OS vault 清理权限。QQ/H5 另以事务 helper 撤销绑定、令牌、会话 ACL、回复资格与断线 checkpoint；历史 sent/unknown 保留，不自动重发或删除外部秘密。
6. 诊断只输出固定状态、版本和聚合数量，不读取 vault 值、不带标识符/路径/URL/提示词/工具输出/日志；明确区分已配置、连接验证、任务实际成功。

## 下一应用切片：生命周期与兼容性

- drain 先拒绝新工作，再通知取消与等待已开始清理；超时保留 pending/unknown，不把丢弃 future 当作副作用已停止。CLI/桌面检查明确协议兼容性；启动/退出/重启恢复用实际本机进程验证。

## 后续：更新、包与资源

- 校验固定可信来源/公钥、原始清单字节、平台、版本、schema范围、单调序号、有效期、长度与摘要；未配置生产信任根时不能由环境/请求选 key 绕过禁用。
- 自动安装和真实签名/发布不在当前授权内。可完成构建与本地包生命周期夹具，但签名证书/生产更新源由用户另行确认；未验证的平台安装必须明确标记。
- 长会话/大历史指标由真实固定数据集测量并记录环境、样本、P50/P95及资源使用；不能把已有20,000事件保留上限或单测超时当作性能实测。

## 完成口径

每切片以独立审查、冻结全量门禁、精确 SHA 三平台 CI 与协议/状态/交接记录为准。QQ、H5、1.0 模块使用明确文件所有权和顺序发布，不把未接线新文件混入已有验证树。

第一应用切片的实际接口和当前边界见 [protocol-v12](protocol-v12.md)，验证证据见 [acceptance-v1.0](acceptance-v1.0.md)。

## 1.0 性能第一切片：索引调度与保留失败

显式 schema v3 索引调度已接入 Store，旧 v1/v2 的启动与备份恢复依次迁移；候选筛选不再反序列化全部已完成历史，仍保留暂停/串行/远端撤权语义。协议见 [v13](protocol-v13.md)，实际同 seed 指标见 [performance-v1.0](performance-v1.0.md)。

1,000 / 5,000 任务的空闲 CPU 和完整 SSE 回放已有明显改善，但 5,000 任务全量快照仍超出 CLI 16 MiB 上限，高峰内存与活动主任务历史检查仍待后续有界读取切片。失败保留，不宣称性能验收全部通过。生命周期及更新 helper 不混入本提交；实际门禁和精确 CI 见 acceptance-v1.0。
