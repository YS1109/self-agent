# Self Agent 0.7 持续会话与实时执行 技术文档

# 目标

让用户在同一会话连续完成项目修改：实时看到回复及执行过程，中途能明确补充当前要求或排队下一条，停止后可继续，重开应用可接上上下文，并能检查实际改动和验证结果。

状态：待开发。当前功能版本仍为 0.6.0。本计划只规定目标和验收，新增指令名称、事件结构与数据库设计需在实现时明确，不应把本文当作可调用的已实现协议。

# 背景

截至 2026-10-28，0.6 已交付主 Agent 直接执行、模型与上下文策略及独立 CLI。Native 推理仍为非流式；现有 SSE 仅实时广播，桌面每 1.5 秒轮询快照；Codex 每回合新建 thread；压缩摘要只作用于当前请求；新的主任务同会话依次排队。

整体方向见 [路线图](roadmap.md)，当前边界见 [实施状态](implementation-status.md)，源码入口和基线验证见 [交接记录](handoff-v0.7.md)。

# 详细设计

## 实施顺序与范围

先完成两项 P0，再完善两项 P1；可按实际规模拆为 0.7.x 发布，未交付项必须继续标注。工作顺序为：协议与持久化设计、后端事件和执行器、桌面和 CLI 消费、会话与摘要恢复、补充指令、更改面板、联合验证。

保留直接主任务与远程编排两条业务路径，继续兼容 `run_agent`、`send_message`、角色快照、计划与布局版本及原回传来源。本轮不扩大至真实通讯平台、复杂图节点、MCP / Skills 管理、完整授权系统或新模型服务协议。

## P0：统一增量事件与流式执行

- 定义回复增量、工具开始和结束、命令输出、上下文压缩、用量及任务终态的统一表达；具体字段在实现协议中确定。
- Native 正确处理分块响应、中文跨字节、工具调用参数分片和中途错误；支持非流式服务的明确兼容策略，不静默重复发起已产生副作用的工具。
- Codex 将实际协议通知转换为相同事件。只展示执行器实际提供的消息和工具信息，不伪造思考过程。
- 事件具有可持久化的顺序和游标。回复分片可有界合并提交；重连不得重复拼接，任务终态只提交一次。
- 增加断线补发；游标失效时明确要求重新取得快照，处理补发与实时订阅之间的竞态。不能只靠进程内广播保存事实。
- 对输出、缓存、慢客户端和日志保留设置有界策略，取消和最终结果不能被大量输出饿死。
- 桌面通过 Rust 桥消费事件，后台认证令牌不暴露给前端。浏览器开发预览继续使用受控代理。
- CLI 提供显式选择的跟随输出能力，保留已有命令的 JSON 输出和退出码语义。新增参数名和消息格式实施时确定。

验收：相同任务的桌面、HTTP、CLI 状态一致；长回复能逐步显示；工具参数不完整时不提前执行；断开、重连、重复事件和慢消费者不丢最终结果；取消后的迟到输出不能恢复任务或追加成功通知。

## P0：持久会话与可复用摘要

- 持久化应用会话与 Codex 执行器会话的关联，序列化同一 thread 的回合；子任务默认继续隔离，不能误接主会话。
- 在当前安装的 Codex 版本上核实恢复协议及能力，再完成实现。仅保存 thread ID 不能视为支持恢复。
- 正常重开桌面、重建执行器进程及 daemon 重启后，可恢复已完成回合的会话；正在执行且结果未知的写入不自动重放。
- 切换执行器、模型、服务、项目目录或有效配置时明确复用和失效规则。恢复失败时保留原始历史，说明原因和下一步；若降级新建 thread，只带入所需历史一次。
- Native 摘要记录覆盖的历史边界、来源和上下文策略，后续请求使用摘要加增量历史；不能遗漏新消息或重复总结同一段。
- 压缩失败、取消、策略变化及重启后的状态可查询；保留原始对话、工具及命令证据。
- 界面显示上下文占用、阈值及压缩状态；实际服务用量和估算值明确区分。

验收：至少连续三轮使用前序真实结果；重启后再续接；跨会话、角色和执行器不串历史；摘要边界外的新增消息完整保留；模型切换及恢复失败具有确定行为，失败不能导致重复文件修改。

## P1：执行中补充、排队与继续

- 输入区明确区分“补充当前任务”与“排队下一条”，显示目标会话和任务；接收和应用分别记录。
- 补充使用现有幂等指令层，保存已接收、待应用、已应用或未能应用的结果；具体枚举在实现时确定。
- 执行器确实支持时注入当前回合；否则在下一次模型或工具安全边界应用。不能把已接收显示成已经影响执行。
- 不为补充要求无提示地中断和重放已执行工具。任务已结束时，明确提示或要求作为下一条提交。
- 区分停止当前直接执行、暂停计划派发和取消整个计划；停止后可发起新的继续任务，并携带已完成结果。
- 同会话队列顺序、任务快照、非阻塞查询和取消、固定回调来源继续成立。

验收：执行长命令时可提交补充和查询；重复补充不重复应用；补充与完成或取消竞态不污染下一任务；不支持即时注入的执行器显示真实等待状态。

## P1：代码改动查看

- 任务真正取得项目执行权后、第一次写入前记录基线；不能把等待期间的项目变化算入本轮。
- 展示实际涉及的文件、文本差异、命令与测试结果；区分项目当前全部改动和能够确认的任务增量。
- 保留用户原有已暂存、未暂存、未跟踪文件；共享工作区内外部修改无法可靠归因时明确标记。
- 处理重命名、删除、二进制、中文路径、大文件、非 Git 项目和敏感文件排除，存储与读取均有界。
- 只查看差异，不附带自动提交、重置、暂存或一键回滚。

验收：项目预先存在用户修改，Agent 再修改同一及不同文件，展示不把全部变化归给 Agent；非 Git 项目和超大输出有明确反馈；取消或失败后仍可检查已经发生的修改。

## 协议与数据兼容

沿用认证、来源、幂等收据和任务终态事务。新增事件、会话关联、摘要及指令使用可迁移持久化结构；旧记录缺少字段仍可读取。大历史避免每次完整复制或扫描。

新增接口先在协议文档中明确版本、请求、错误及恢复语义，再同步共享类型、后台、桌面桥、浏览器代理与 CLI。实现时新增下一份协议文档并更新 AGENTS.md 的当前协议入口，不提前修改 0.6 的协议含义。

## 联合验证与交付条件

1. 在隔离项目连续完成读取、修改、测试和修复，观察桌面与 CLI 的真实增量和终态。
2. 运行中断开事件连接、切换会话、重开桌面及重启后台，检查事件补发、会话关联和原数据保留。
3. 交错提交补充、下一条、查询和取消，验证顺序、幂等、明确作用目标及迟到结果处理。
4. 带已有用户改动运行成功、失败、取消任务，检查基线和差异，不覆盖用户文件。
5. 原有八组回归保持通过，并增加针对流式分片、恢复、摘要边界、补充竞态及差异归因的有效测试。
6. 中文、灰蓝明暗主题、80% 至 120% 缩放、窄窗口、下拉及输入焦点回归通过；三平台 CI 通过。

默认 CI 不消耗云端额度。真实模型验证使用隔离数据和项目，明确记录 Native 与 Codex 分别验证了什么；未测的长上下文或跨平台能力不得记作通过。更新实施状态和交接记录后再报告交付。
