# 0.5 迭代计划

状态：已实现并完成本机验证。范围：自然语言修改计划、统一指令与会话路由、真实主 Agent 闭环验证，以及可编辑流程图。实际交付与验证结果见 `implementation-status.md`。

本文保留 0.5 当时的范围与后续设想。当前日常入口已在 0.6 改为主 Agent 直接执行；后续版本顺序以 [分版路线图](roadmap.md) 为准，接手先读 [0.7 交接记录](handoff-v0.7.md)，不要依据本文末尾的历史排序直接启动通讯平台开发。

## 目标与优先顺序

用户要的是可以自由调整、持续推进的编码工作流。本轮把表单、画布和自然语言接到同一套计划服务，桌面与模拟远程入口共用指令语义。耗时模型请求不得阻塞执行和结构化管理。

### P0 一、用自然语言调整当前计划

输入区明确区分“新目标”和“补充当前计划”，显示目标会话及计划，避免一句补充意外生成独立计划。现有开始、暂停、取消按钮保持可直接使用。

主 Agent 接收已有计划的目标、已完成结果及版本号，输出后续节点调整建议。桌面展示增删改摘要；用户应用后仍走现有 `patch_plan` 的校验与事务，不给模型新的直接写入权限。

只修改尚未开始节点，允许追加修复和验收。运行状态变化导致版本过期时，不能静默覆盖；保留补充要求并允许基于最新版本重新生成建议。耗时理解和建议生成不能阻塞已有任务及结构化管理指令。

验收示例：计划执行时输入“先补回归测试，再继续界面修改”，建议只改变后续工作，保持已完成节点、角色快照、预算和回调来源。

### P0 二、统一指令接收与会话路由

桌面与模拟远程入口均能明确选择本地会话、选择已有计划、补充要求、查询进度和暂停／恢复派发。查询直接读取持久化快照，结构化控制直接调用应用服务，不等待主模型理解。

复用现有来源、会话选择和幂等命令信封；指令指定的计划必须属于所选会话，不根据当前桌面焦点猜测目标。每个入口的会话／计划选择互相独立。消息接收后立即返回凭证，计划修改建议异步生成并持久化，需显式应用。

计划最初的回调来源保持不变；从另一入口补充要求不会把后续任务的通知迁移到新入口。真实通讯平台鉴权、配对和收发仍属于后续版本。

### P0 三、验证真实主 Agent 的完整执行闭环

目前的真实 Codex 实测采用确定性规划与回顾。新增显式启用的端到端实测，用配置的真实主模型生成计划、读取实际失败、提出修复和验收，再由 Codex 执行。

继续使用隔离小项目，验证目标中途补充、暂停恢复、失败修复、最终回调；保存脱敏的执行摘要和实际证据。该测试与默认 CI 夹具分开，默认 CI 不使用云端额度。

验收要求：主模型不能靠完成文字通过失败节点；只有有效的修复关系和实际验收命令证据允许父计划完成。预算耗尽、模型异常或用户取消必须停在可解释的状态。

### P0 四、可编辑流程图

现有 React Flow 依赖图升级为任务编排画布：

- 新增任务、删除允许删除的任务，拉线创建依赖、删除连线；阻止自依赖、重复依赖和循环依赖。
- 点选节点编辑标题、目标、执行角色、修复／验收关系与验收命令，并查看实际状态、结果和命令证据。
- 画布与表单共用一个编辑草稿，通过现有带版本的计划修改接口保存；运行中的历史节点定义锁定，允许调整尚未开始节点。
- 拖动节点保存布局；布局单独版本化，不改变执行计划版本、不触发调度，也不让自然语言建议失效。旧计划缺少布局时自动排布。
- 支持展开画布与返回对话，切换视图保留草稿；明暗主题、中文和灰蓝配色保持一致。

第一版执行结构仍为 DAG。条件分支、显式循环、人工确认节点与模板库需要额外执行语义，留待后续迭代，不以普通节点外观模拟已支持。

## 联合验收

1. 从远程模拟入口选择会话并生成计划，在桌面画布调整任务和连线、保存布局；重启后可恢复。
2. 开始执行并暂停派发，补充“先增加回归测试，再继续”，异步建议生成期间仍可查询进度、切换会话和管理其他任务。
3. 比较建议与现有计划的增删改，显式应用；过期版本、非法环路、修改历史节点均拒绝，保留用户输入和本地编辑。
4. 切换远程入口的当前会话后，原计划的子任务和最终回调仍回到原来源；重复请求不重复创建建议或执行任务。
5. 真实主模型规划与修改、真实 Codex 失败／修复／命令验收得到实际证据；取消和预算耗尽均有明确终态。默认 CI 不消耗云端额度。

## 后续：可检查的项目变更

把现有“更改”面板接到真实项目状态，支持查看改动文件和 diff，与任务、命令结果相邻展示。已有用户改动必须保留，界面明确区分项目当前改动与能够确认的任务增量，不能把工作区全部变化都归给 Agent。

验收要求：项目包含未提交修改时能正确展示；不执行 reset、自动提交或覆盖用户文件；非 Git 项目明确说明可用信息。

## 后续：首个真实通讯渠道

建议作为紧随其后的独立迭代，复用 0.5 的“补充当前计划”语义，让桌面与远程使用同一种指令：

- 渠道适配器统一接收消息 ID、发送者、会话、回复关联和正文；不把平台字段渗入调度核心。
- 完成身份配对、入口到本地会话的绑定、列出与切换会话，防止发错项目。
- 同一消息重复投递只处理一次，主 Agent 接收后立即确认，子任务继续异步执行。
- 子任务与最终计划分别回到最初渠道和会话；通知失败独立重试，不重复执行任务。
- 先接一个明确选定的平台，测试断连、重连、消息重复、切换会话和回调失败，再扩展其他渠道。

H5／App 在渠道鉴权与远程管理协议稳定后复用同一服务；本轮不增加公网监听或移动端外壳。
