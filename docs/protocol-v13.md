# 协议 v13：有索引的后台调度（1.0 性能第一切片）

包版本仍为 0.6.0；本协议不是完整 1.0 或长历史容量验收。此前维护接口见 [v12](protocol-v12.md)，网关及其 v2 迁移见 [v11](protocol-v11.md)。HTTP、事件及命令数据格式在本切片不变。

## 1. 显式 schema v3

当前 `user_version=3`；ledger 必须按顺序精确包含：

1. `self-agent-schema-v1-atomic-baseline`
2. `self-agent-schema-v2-gateway`
3. `self-agent-schema-v3-indexed-scheduling`

从 v0/v1/v2 启动时，依次验证旧结构、执行缺少的迁移并在同一事务提交。v3 仅新增七个可信表达式索引：tasks/plans/coordinator_jobs/deliveries 的状态与创建时间，以及 tasks/plans/coordinator_jobs 的来源与状态。没有修改历史 body、命令收据、事件序号或执行权限；任一步失败整体回滚。当前库必须保有这些精确定义，缺失或同名不同定义阻断，不在读取时自动补建。

较新版本及冲突 ledger 仍由只读启动门禁拒绝。旧版本可信备份在隔离数据库迁移至 v3，复核索引后才允许恢复替换；恢复撤销执行与远端权威的规则不变。索引不是备份来源认证，也不扩大既有任意 SQL schema 验证承诺。

## 2. 调度语义

- 候选查询在 SQL 中只读取 queued 非 plan 任务、pending 规划请求、running 计划与本地 pending 投递，不再每次空闲轮询把全部已完成任务 JSON 读入 Rust。
- 任务和规划请求仍按创建时间、同时间原插入顺序领取。任务队列没有隐藏 `LIMIT 1`；前方暂停计划或同会话串行阻塞不能遮住后方可运行任务。
- QQ 撤权检查只读取对应来源的活动记录，但不加隐藏数量上限；原检查与终止事务、未知结果和不重放规则不变。网关继续沿用其既有授权及容量边界。
- 此切片只改善空闲历史扫描和锁竞争；主任务有候选时的同会话前序检查仍读取历史。不得由空队列索引测试推断所有活动调度成本恒定。

## 3. 实测与保留失败

[性能记录](performance-v1.0.md) 保留原始失败与同 seed 对照。Linux debug 下，1,000 / 5,000 已完成任务的短空闲窗口 CPU 从约单核 100% 降至约 1.5%；完整 20,000 条事件回放由 30 秒超时变为两组各 3/3 在约 1.1–1.7 秒完成。迁移前后原 seed 摘要、历史逻辑摘要和计数不变。共享环境、小样本不是性能 SLA；未测 release、其他 OS 的资源和真实模型。

**尚未解决**：5,000 任务快照仍为 40,620,326 bytes，CLI status 与单任务查询仍因既有 16 MiB 限制拒绝；后台峰值内存仍高。下一切片实现有界快照、历史分页及真正的单任务读取，不提高上限、丢弃历史或隐瞒缺口。本切片不包含未接线的生命周期/更新 helper。
