# 协议 v10：受限 QQ 身份与可靠投递（0.9 实施中）

本文件描述当前已接线的本机/远端接口契约，**不是 0.9 全部门禁通过或真实 QQ 验收记录**。叠加 v7 的预算/决定和 v8/v9 的托管能力/凭据边界。外部传输和测试范围见 [0.9 迭代计划](iteration-v0.9.md)。模块、实际 Store/API、联合夹具与真实平台验收分别记录，不能互相替代。

## 信任边界

- QQ 长连接经过固定官方域名鉴权，只证明消息来自该 AppID 下的 QQ 平台；不等于发信者被允许操作本机。
- 绑定键包含 AppID、事件明确的 sender OpenID、C2C/群类型和具体对话；群事件使用 member_openid，不把群管理员、QQ 号、显示名或消息里的 actor 当作身份。
- `SourceContext` 仅用于路由。受限命令由 daemon 内部入口携带已校验的 principal、绑定修订和消息 route；不能经公开 owner API 自报 QQ 来源。
- 接收和执行指令的事务内检查绑定有效期、状态/修订、会话 ACL、操作权限。运行中的 QQ 来源任务在新模型/工具操作前继续检查撤销；撤销不回滚已发生副作用。
- 本机 bearer、系统凭据、MCP 管理、设置、清理解除隔离、授权决定 API 永不转交 QQ；未知命令拒绝，不做任意 JSON/HTTP/URL 代理。

## 本机配置、凭据与接口

下列接口仅走既有本机 owner 鉴权；QQ 消息不能调用，也不能指定任意 owner kind、凭据目标或地址。

| 方法与路径 | 契约 |
| --- | --- |
| `GET /api/v1/qq` | 公开配置、持久连接状态、绑定、入站/投递元数据及 QQ 凭据操作；无 secret/原始凭据引用 |
| `POST /api/v1/qq/commands` | `{id, command}`；允许 `configure`、`issue_pairing`、`confirm_binding`、`revoke_binding` |
| `GET /api/v1/qq/commands/{id}` | 原管理收据或 `null`；重放签发收据不再显示配对码 |
| `POST /api/v1/qq/credentials/{config_id}` | `{id, expected_revision, secret}`；独立 QQ 系统凭据登记/轮换 |
| `DELETE /api/v1/qq/credentials/{config_id}` | `{id, expected_revision}`；先停用、撤权、解绑，再领取删除意图 |
| `POST /api/v1/qq/credentials/cleanup/{operation_id}` | `{id}`；明确清理指定未绑定遗留引用 |
| `GET /api/v1/qq/credential-operations/{id}` | 原凭据操作公开状态或 `null`，不是再次执行 |

配置单例使用规范 UUID 和 revision CAS；首次创建停用。生产模式固定官方令牌地址 `https://api.bot.qq.com/app/getAppAccessToken`，不接受用户指定端点。只有进程显式夹具开关允许 loopback 测试端点；夹具模式清楚标示，不读真实系统凭据。启用要求作用域匹配的凭据元数据或可信进程夹具，不能把元数据就绪当成系统凭据可读或 QQ 已连接。每次配置变更增加修订、清空旧检查点；带凭据引用时更换 AppID 被拒绝，必须先解绑。停用、更换 AppID、解绑会撤销 active/pending 身份和未领取配对码；重新启用不恢复旧授权。

QQ 凭据绑定由配置 UUID、AppID、固定令牌地址及 official 模式派生，独立 purpose 为 `qq_client_secret`；启停、回复额度、配置修订不改变该绑定身份。数据库只保存私有引用和意图元数据，不接收 secret 值或 secret 指纹。重复 set 先返回原元数据收据，本次输入不写入；轮换只允许全新引用。`pending → inflight` 必须提交后才允许系统调用；成功仍要 CAS，过时新引用记作 orphaned，旧引用保留待清理审计。Unknown/重启不自动重放；显式清理不改写原操作 Unknown 历史，使用独立 cleanup_status。普通操作 128、遗留引用 64、额外清理审计 128 的上限与可能遗留/旧引用槽在调用前预留，不靠删除 Unknown 记录腾空间。

管理收据 `completed/rejected` 与凭据操作 `pending/inflight/completed/rejected/unknown/orphaned/cleanup_required/cleaned` 是不同层。连接状态保存真实更新时间，读取不伪造更新时间；重启报告 disconnected/disabled，不把可恢复 session 当成 ready。系统凭据不可读时不循环弹出授权，需明确更改配置修订后再尝试。

## 配对和授权

本机所有者生成不超过 10 分钟的一次性随机码，只在签发回执显示；数据库仅存摘要。远端 `/配对 码` 仅创建待核对记录。配对原文不进 inbox、事件或日志；耐久输入使用带 AppID 域隔离的摘要，重发同一消息返回原处理结果。

本机确认必须包含待绑定 principal ID、预期 revision、完整待核对 identity 和明确 grant；确认后还须满足下方固化的安全接收窗口，旧消息不会因此变成待执行指令。grant 包含允许会话、操作权限、任务限制和最长 30 天有效期。查看、结果、运行、取消、回答、编排、新建分别授权；启动或恢复编排还必须有运行权限；群内结果/问题展示另需 `share_group_results`。新会话只能复制已授予会话的项目根，不允许远端指定本机路径。新会话 ACL 和指令结果一起提交。

默认推荐任务限制为禁 shell/MCP、文件写入询问、300 秒和 32 KiB 输出；它不是自动授权，仍需本机明确确认。所有限制与全局/角色/原继续任务取交集；Codex 无法执行的严格限制拒绝，不静默放宽。

## 入站、游标与路由

1. WS Hello → Identify/Resume；Ready/session、机器人 user ID 与序列号保存在 daemon SQLite，并由 config UUID+revision 栅栏限定。session/user ID 为不超过 128 字节的 ASCII 字母、数字、下划线或连字符。同 session 序号允许相等去重、不允许倒退；切换 session 必须先耐久清除旧检查点。只在对应 inbox/检查点事务提交后向传输 actor 确认推进；恢复时可能先收到补发事件再收到 RESUMED，每项分别等提交。
2. `AppID + message_id` 是输入去重键；事件 ID 是附加别名，不用传输 seq 当业务幂等键。同消息同规范内容返回原收据；相同键改变身份、内容或平台时间戳拒绝。
3. 配对以外的有效文本会进入受限指令解析。已过期但尚未执行的旧消息不因重连而自动执行；过期判断在去重后进行，不把当前时间混入规范内容摘要。
4. reply route 每消息固定：principal/revision、C2C/群目标、message_id、平台时间戳、被动窗口。会话选择按 principal+对话单独保存，切换不会改变旧 route。
5. 接收确认和任务完成是不同投递项。模型流和工具输出不逐 token 向 QQ 推送；查询和取消不等待模型或项目锁。受限命令、主指令收据、派生会话 ACL、选择、ACK 入队同事务；失败全回滚后另事务记录通用拒绝，不反射原始错误。无效非 READY 事件可忽略正文并推进已验证 session 检查点；无效 READY、同消息冲突或存储容量错误不能确认输入提交。

## 远端命令和最小输出

文本以 `/` 开头时只识别固定中文指令，否则是主 Agent 目标，最多 8192 UTF-8 字节。命令包括 `/会话`、`/选择`、`/新建`、`/运行`、`/状态`、`/结果`、`/取消`、`/补充`、`/继续`、`/问题`、`/回答`、`/编排`、`/计划`、带修订的计划启动/暂停/恢复和计划取消。任务/会话/请求均要求完整 UUID，不猜测短 ID。`/计划` 不带 ID 时列出当前所选会话最近 5 个计划的 ID/状态，可在原通知过期后重新发现草稿；不会自动启动。

回答只可操作 question，绝不能借此批准 approval。默认回复限于状态/关联 ID；不提供原始工具日志、全量快照、任意文件读取或项目路径字段。显式结果查询还需结果范围及群受众授权，仅提供有界摘要并替换已知项目根；不能保证识别用户或模型正文中任意未知敏感信息，因此这仍是明确的数据分享权限。平台不支持结构化卡片时使用文本，不发送不可用交互按钮。

任务派发、编排领取/结果提交及执行控制检查实际验证 QQ 来源 actor 与不可变 route 的 principal、当前绑定修订、配置启用和授权期限；不以五分钟被动回复期限取消仍获授权的长任务。撤权先保留首个 stop_reason，再取消关联活动任务/计划/编排，阻止迟到编排结果应用。确认授权时验证当前执行器支持；后来切换默认执行器不阻止取消旧受限任务等管理操作，新建任务仍按实际执行器拒绝不支持的严格权限。

## 接收资格与时钟异常

确认或重新配对时，在同一事务固化 `input_after_ms = max(本机确认时间 + 30000, 已忽略平台时间高水位)`。新控制消息的平台时间必须**严格晚于**该点；相同毫秒不能证明在确认之后。正常时钟对齐时约需等待 30 秒，UI 单独显示安全接收窗口，不把它与授权到期混淆。窗口内发出的旧消息之后不会自动执行，应在窗口之后发送新消息。授权到期不晚于安全接收点的确认被拒绝。

此策略依赖 QQ 官方 Dispatch 中的原始平台时间，不使用用户正文提供的时间；正常接收仅容许本机当前时间前方至多 30 秒。已经见到的更远未来时间不会被悄悄忘记：`ClockSkew` 路径在同一 SQLite 事务保存一行时钟异常高水位并推进游标。该独立异常高水位也作为现有绑定的新输入下界，防止校正本机时钟之后重放原消息而执行。普通未配对流量不能抬高这个异常下界，也不修改既有绑定修订或它的固化窗口；已耐久接收消息的去重仍先于时间检查，已接收的工作不因此重放或撤权。

时间高水位跨重启保留，回滚与游标回滚一致；异常高水位极远时刻意停止新接收/拒绝无法覆盖它的授权，而不是清空证据或自动重发，需检查本机与平台时钟。汇总计数最多 `9007199254740991`，没有按陌生身份增长的表。它解决永久存储耗尽，不承诺阻止所有网络/CPU 洪泛；接入平台、WS 有界积压和本机资源仍是运行边界。

## 可靠 Outbox

- 每个逻辑回复全局唯一（`ack:INBOX_UUID`、`completion:TASK_UUID`、`coordinator:JOB_UUID`），同 key 不得改投其他 route。`msg_id + msg_seq` 在入队时固定。回复 route 另存本机 `accepted_at_ms`；初始及后来收紧的窗口都以平台时间与本机接收时间中较早者计时，未来时间偏差不能延长窗口。旧记录缺少该字段时收紧发送校验保守关闭。默认最多 C2C 4 / 群 5 条，每条 source message 共用配额，不因重试重新分配序号。
- 本地事务领取 `pending → sending` 并保存 attempt/claim 后，释放数据库锁再请求平台；发送前再次检查配置、绑定修订/撤销和期限。
- 成功必须保存平台 message ID。明确 429 才可在同一被动窗口内延后，并保留序号；其余明确拒绝为 failed，5xx、网络中断、成功响应损坏或发送后本地提交失败为 unknown。
- sending 在重启恢复为 unknown，不自动回到 pending；没有跨平台“恰好一次”承诺。未知投递可在本机查看和通过新消息查询任务，不能用新序号自动重发。
- 官方 C2C 时效描述不一致；应用保守采用不超过 300 秒且允许收紧。超过窗口为 expired，与任务成功/失败分开，不自动转主动推送。
- 主任务/计划终态通知仅包含状态与 ID，不复制 result/error/tool 输出；子任务不单独占回复额度。编排草稿通知仅含作业/计划状态，过期可用新消息查询。主 delivery 的 source/session 必须与原任务一致，不能用另一个有效身份的 route 转发。通知入队错误用 SAVEPOINT 回滚序号再记录 not_queued，不改任务结果；后续 outbox unknown 同步到 delivery，不触发主 delivery 自动重放。
- 取消观察不等于取消已在途请求；撤权不能保证召回消息。未知结果保留明确记录，不把网络异常描述成未发送。

## 本地资源上限

单消息最多 8192 UTF-8 字节、16 个事件别名。入站总记录最多 10000、待处理最多 256、投递总记录最多 10000；到限拒绝新记录，不删除 unknown 或偷偷重放。未配对普通输入、无效配对码和安全窗口内的新输入不进入控制入站表、不保存身份/消息/别名行，只更新一行饱和计数及时间高水位，并与网关游标一起提交。有效、未过期的已签发配对码只允许一个新入站占位，重复同一消息先走耐久去重。已获接收资格的历史达到保留上限后连接会报告不可继续，需在后续维护/归档流程处理；当前不提供自动历史清理，1.0 的备份/诊断不能忽略这个边界。
