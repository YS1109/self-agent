实际 Store 的覆盖包括：原子输入/检查点及冲突不 ACK；源 actor/route 固定与会话选择隔离；全局/授权/角色限制取交集；新会话、ACL、选择、ACK 和收据遇到入队故障全回滚；远端回答使用 QQ actor、不能批准 approval；撤权取消任务/编排并保留首个停止原因；默认执行器改为 Codex 后仍可取消旧 Native 任务，而新的不兼容受限任务被拒绝；凭据引用跨 provider/QQ 不通用、公开快照不含引用或 secret；任务完成结果与通知 unknown 分开、不重放。

传输/runtime 曾发现并修正的两个回归：Resume 可先补发事件再发 RESUMED，不能假定恢复首事件必为 RESUMED；同步 SQLite 入站曾阻塞 Tokio worker；入站、配置检查、授权检查、领取与完成记录改为等待阻塞线程事务。单线程 Tokio 下持有真实 SQLite 互斥锁、在 COMMIT 前设栅栏的回归仍持续发出旧游标心跳，提交前不会 ACK 新事件。修正不改变“入站与游标提交后才 ACK”的要求，不以忽略超时或跳过持久化使测试通过。


## 入站可用性与重放安全修正

独立审查发现陌生消息可耗尽原共享 lifetime 入站容量，发布前已改为一行饱和忽略汇总，不删除已经接收的指令、sent 或 unknown 历史。新测试覆盖 24000 次不同陌生身份/无效配对码、有效配对码单占位、严格相等边界、允许的 +30 秒旧消息、重新配对、重启、时钟回拨、事务回滚，以及真实 Store 的“未来时间先被忽略、确认授权、校正时钟后重复原 ID”流程。

随后又补已活跃绑定遇到未来时间异常的独立持久下界；普通未配对消息不会移动该下界。UI 显示普通确认窗口与异常时钟状态，窗口内旧消息不自动排队。模拟时间偏差还发现并修正了收紧被动窗口的计时基准：使用原平台时间与已固化本机接收时间的较早值，不能因未来平台时间获得更长窗口。最终全套包含 114 项 QQ 定向测试（其中实际 Store 15 项）；兼容旧开发版汇总表的迁移使用 SAVEPOINT 原子添加与回填时钟下界，故障回滚和嵌套事务重试已验证。

## 实际进程联合夹具覆盖

`scripts/qq_smoke.py` 启动真实 daemon、CLI、本地 QQ HTTP/WebSocket 服务和 Native 模型服务，未调用外部平台：

1. 官方形状的 token/gateway/Identify/READY；CLI 查询、签发和只读收据不再暴露配对码；本机逐次确认后才接受远端控制，未配对输入无回复/任务。
2. 实际 read_file 工具与固化限制；同一消息重复事件只执行一次；接受/完成回复始终使用原 msg_id/msg_seq，默认通知不含结果，明确查询才分享有界摘要。
3. `/问题` 和 `/回答` 固定请求修订，持久 decision_actor 是 QQ principal；不能把回答变成本机 write_file 审批。
4. 模型请求刻意阻塞期间，状态查询和取消仍完成。
5. 群内结果授权单独检查；明确 429 保留同一 body/序号；丢失响应记 unknown，daemon 重启 Resume 与重复事件均不重发该消息。
6. 实际受限编排草稿、计划查询与启动、父任务完成通知；子任务不单独占额度，撤权后不能新派任务。

## 已实现，不等于已进行真实平台验收

- 生产地址固定官方域名，测试端点仅由显式进程夹具模式注入 loopback；已接单配置修订监督器与入站/命令/投递循环。
- 本机 owner 配置、配对确认/撤销、QQ 专用凭据意图与查询 API，以及 App 管理入口、CLI 和路径白名单已接线。配置成功、凭据绑定、系统凭据可读、平台鉴权、连接、任务结果和投递结果各自独立。
- 系统凭据适配器已有生产代码，QQ 生命周期通过内存夹具/私有引用检查验证；没有写入真实 OS 凭据，也没有以模拟成功宣称平台连接成功。
- 通知使用不可变被动 route，Unknown 不重放；主任务/计划状态与编排草稿通知不包含原始结果/错误，完整结果仅能在另行授权的查询中分享有界摘要。

## 保留边界

C2C 文档时效冲突采用不超过 300 秒的保守应用策略，不声明平台保证；无主动推送后备。撤权不能召回在途消息，未知投递不能解释为肯定未发送。摘要分享不承诺识别任意未知敏感正文。配对码只在首次签发响应显示，公开快照/重放收据不显示；secret/token/私有引用不得进入公开日志或快照。入站/投递到限拒绝新增，不删除 Unknown 或自动重放来腾空间；自动归档和完整备份/升级仍属于后续稳定性切片。
