# Self Agent 0.8 自主执行与能力管理

日期：2026-10-28。状态：首个执行控制切片已实现且本地模拟门禁通过，提交及 CI 核验待记录；后续能力仍为实施计划，不表示完整 0.8 已交付。

## 顺序与边界

先交付任务预算、Native 修复与复验、可追踪问题和逐次授权，再交付应用管理的 MCP / Skills 与命名服务、凭据生命周期。桌面、HTTP、CLI 共用 Rust 持久化规则；不以界面按钮或模拟成功文案替代真实工具调用。

- 任务入队固化有效配置；角色和任务只能缩小所有者设置的上限。
- Native 命令依然需要 `HARNESS_ALLOW_COMMANDS=1`，它是可信本机 shell，不是文件系统或网络沙箱。任务权限不能把 shell 描述成受项目限制的安全工具。
- Codex 的一次 app-server 回合不等于一次模型请求；无法执行的严格限制必须在写入前拒绝，不能静默忽略。
- 问题回答与授权是不同记录。拒绝、过期和取消不产生授权，已执行或结果未知的写入不自动重放。
- 默认测试仅使用本地模型/协议夹具和隔离项目，不调用真实模型、外部服务或持久化真实凭据。

## 执行控制验收

1. 预算包含模型请求（含压缩）、运行时长、可安全重试次数、修复轮次及输出字节；达到上限保留结果和明确原因。
2. 验收命令实际运行，保留故意失败、修复、原命令复验记录。最终修改后的成功证据才满足验收，模型文字不算证据。
3. 问题/授权记录绑定任务、修订和具体操作。重复、迟到、参数改变、取消及重启均不能导致重复副作用。
4. 控制操作不等待模型请求或 SQLite 锁；状态经快照/事件同步到三个入口。
5. 修改设置不改写旧任务；旧数据库可读，历史失败不被覆盖。

## 后续能力验收

MCP 服务实际初始化、列工具、受控调用，故障隔离；Skills 启停实际改变任务上下文。区分本应用管理与外部 Codex 自行加载能力，发现配置不表示调用验证。命名服务隔离凭据，主机变更不转发旧密钥；系统凭据不可用时不得退化为明文存储。

完整实现、检查结果、残留限制逐切片记录在实施状态与对应协议中；生产签名、发布、通讯平台选择和扩大本机执行权限不属于此计划的自动授权。

首个切片的具体测试与未验证项见 [执行控制验收记录](acceptance-v0.8.md)。
