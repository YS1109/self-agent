# Self Agent 分版路线图 技术文档

# 目标

构建以主 Agent 日常编码为中心的个人工作台：用户持续提出目标，Agent 在项目内读取、修改、验证和修复；桌面、无头 HTTP、CLI、未来通讯与移动端共享同一 Rust 后台、会话和任务记录。

规划覆盖 0.7 至 1.0。近期先改善日常编码的连续性与可观察性，再完善自主执行和能力管理，随后接通真实远程入口。各版本需有可复现的验收，不以模拟数据或完成文字代替实际执行。

# 背景

更新日期：2026-10-28。当前已交付版本为 0.6.0，具体能力见 [实施状态](implementation-status.md) 和 [当前协议](protocol-v5.md)。

用户已明确：Rust 服务端、成熟桌面前端、Codex 式会话工作台、简体中文、灰蓝主题且不使用绿色；日常由主 Agent 直接工作，子 Agent 派发与流程图主要服务显式远程编排；必须保留独立 HTTP 和 CLI 入口。

当前短板包括非流式模型输出、Codex 每轮创建临时 thread、原生摘要不能跨任务复用、执行中补充仅能排队、缺少真实代码差异面板。真实通讯、移动客户端、应用内 MCP / Skills 管理尚未实现。

版本顺序是规划，具体字段、接口和日期在各版本实施前确定。候选能力不构成已经交付的承诺，也不自动授予外部发布、通讯发送或扩大本机执行权限。

# 详细设计

## 固定产品方向与技术边界

- 继续使用 Rust daemon、SQLite、Tauri 2、React / TypeScript；不为每个客户端复制任务策略或编排逻辑。
- 桌面默认流程为目标、主 Agent 工具循环、验证与修复、回复。普通对话无需先生成草稿、启动计划或选择子 Agent。
- 远程入口可直接调用主 Agent，也可显式启动编排。已有 DAG、角色预设、计划修改、暂停恢复、验收与原来源回调保持兼容。
- 数据库是任务、计划、消息、事件与投递状态的事实来源；查询、取消等管理操作不等待模型请求或项目写锁。
- 模型统一上下文和压缩策略，子 Agent 可逐项覆盖；新任务保存有效配置快照，修改预设不改写历史。
- 所有客户端均需保留中文、灰蓝明暗主题及可调缩放。模型名、路径、代码和用户原文不翻译。

## 0.7：持续会话与实时执行体验

范围和实现顺序详见 [0.7 迭代计划](iteration-v0.7.md)。

| 优先级 | 交付项 | 验收 |
| --- | --- | --- |
| P0 | Native / Codex 增量回复和统一执行事件 | 桌面、HTTP、CLI 可观察同一任务，工具与命令记录可展开 |
| P0 | 持久事件游标、断线补发与快照恢复 | 重连不丢已提交事件、不重复拼接文本，慢客户端不拖住任务 |
| P0 | Codex thread 续接、原生摘要复用 | 同会话多轮和重启后可续接；恢复失败可解释且不自动重放写入 |
| P1 | 执行中补充与排队下一条 | 明确目标和接收、应用状态；停止后可基于已有结果继续 |
| P1 | 本轮代码差异与上下文用量展示 | 区分项目已有改动和可确认任务增量，估算与实际用量有标记 |

先完成 P0，再交付 P1；可拆成 0.7.x 小版本，拆分时在实施状态明确实际范围。0.7 不扩大到复杂图节点、真实通讯平台或新的模型服务协议。

## 0.8：自主执行与能力管理

目标是在已有权限和预算内完成“实现、测试、发现失败、修复、复验”，减少用户反复发送“继续”，同时清楚解释为何完成、停止或等待输入。

| 优先级 | 交付项 | 验收 |
| --- | --- | --- |
| P0 | 按任务配置模型轮次、运行时长、重试与输出预算 | 配置持久化并固化到任务；预算耗尽停止且保留结果和原因 |
| P0 | 主 Agent 修复与复验闭环 | 保留原失败证据，实际运行验收命令；文字声称通过不能替代退出码 |
| P0 | 待回答问题与授权交互 | 请求、作用范围和用户决定可追踪；拒绝或超时后按明确规则停止或等待 |
| P1 | MCP / Skills 应用内管理 | 可配置、启停、查看来源和检测状态；配置错误不使其他会话不可用 |
| P1 | 任务及角色权限、能力边界 | 区分本机与外部写操作；角色和模型输出不能自行提升权限 |
| P1 | 多服务配置与凭据生命周期 | 命名服务切换不串密钥，使用系统凭据存储的具体方案按平台确认 |

建议先交付执行预算、修复闭环和授权，再用 0.8.x 接入能力管理。工具配置需要区分本应用管理的能力和本机 Codex 自行加载的能力，不能把“已发现配置”当作“已通过实际调用验证”。

依赖 0.7 的持久会话和统一事件。用隔离项目验证故意失败、修复、复验、预算耗尽、授权拒绝、取消及重启；外部写入测试使用明确授权的测试资源。

## 0.9：首个真实通讯入口

目标是通过一个实际通讯工具管理和继续本地会话，长任务执行期间仍可查询、取消、切换目标，并收到准确回调。

| 优先级 | 交付项 | 验收 |
| --- | --- | --- |
| P0 | 一个实际 ChannelAdapter | 选定平台后打通收取、接收确认、回复和完成通知 |
| P0 | 身份配对、授权、撤销绑定 | 未绑定身份无本地控制权，撤销后停止接收控制及继续投递 |
| P0 | 列出、创建、选择与回复会话 | 按身份及外部对话隔离选择，回复旧任务按原关联路由 |
| P0 | 幂等输入和可靠 Outbox 投递 | 重复消息不重复执行，失败通知独立重试，切换会话不改变回传目标 |
| P1 | 结构化卡片、任务摘要与授权产物 | 平台能力不足时退化为文本，不默认回传完整日志或本机路径 |

平台待用户选择，不能因为开发机已有某个通讯插件就视为已选定。优先评估平台提供的出站连接；需要公网 webhook 时，再明确签名校验和部署方案。复用已有本机 API 与指令层，不把平台字段放进调度核心。

依赖可对远程身份施加的权限和可恢复事件。验收覆盖断连重连、重复消息、回错会话的拒绝、回调超时、平台限流、撤权和 daemon 重启；发送未知结果要单独标识，不承诺跨平台恰好一次送达。

## 0.10：远程网关与移动 H5

目标是手机浏览器可查看并继续桌面的同一会话，任务始终由本机 daemon 执行并保存。

| 优先级 | 交付项 | 验收 |
| --- | --- | --- |
| P0 | 设备配对、认证出站连接与远程网关 | 本机无需直接开放公网控制端口，设备与身份授权可撤销 |
| P0 | H5 会话、输入、进度、取消和待回答问题 | 与桌面及 CLI 状态一致，刷新和重连后恢复 |
| P0 | 离线、重连和重复提交语义 | 设备离线明确提示，网关默认不缓存待执行指令 |
| P1 | 移动端代码差异与产物查看 | 大输出有界、访问鉴权，窄屏仍以对话为中心 |
| P1 | 多设备目录 | 在确有需求时增加，明确当前控制的设备与会话 |

网关运行位置、托管成本、身份提供方和域名均待确认。远程浏览器不得直接取得本机 daemon 管理令牌；网关不成为另一套任务数据库。数据保留和传输策略实施前形成独立协议。

依赖 0.9 的身份和路由语义以及 0.7 事件恢复。验收包括移动网络切换、配对过期、设备撤销、多个入口同时操作和长任务断线后恢复。

## 0.11：独立 App 候选

独立 App 是候选里程碑，由 H5 使用反馈决定是否启动，不阻塞 1.0 桌面及无头版本发布。

- 根据需要增加系统通知、通知跳转指定任务、附件选择和更好的移动输入体验。
- 继续复用网关、身份、会话和指令协议；移动端不复制 Agent 核心或持有不必要的本机凭据。
- 平台、技术栈、分发方式和通知服务待确认，不在当前文档中预选框架或承诺上架。
- 验收关注后台恢复、退出登录后的通知停止、任务定位准确、弱网重试与权限撤销。

## 1.0：稳定发布

目标是已声明能力可重复安装、升级、使用、排障和恢复。1.0 的核心是桌面与无头执行；通讯和 H5 仅在各自通过验收后进入发布范围，候选 App 不作为发布前置条件。

| 优先级 | 交付项 | 验收 |
| --- | --- | --- |
| P0 | 数据迁移、备份恢复与协议兼容 | 从已有版本升级保留会话和配置，失败路径不破坏原数据 |
| P0 | 三平台安装与后台生命周期 | 安装、启动、退出、升级、取消及崩溃恢复均有可复现验证 |
| P0 | 凭据保护、权限检查和日志脱敏 | 所有已接通入口遵循相同授权，导出资料不含凭据 |
| P0 | 发布校验、签名与更新策略 | 签名身份、更新源和基础设施由用户确认，校验失败不安装 |
| P1 | 诊断与用户文档 | 可导出脱敏诊断，准确区分配置可用、连接通过和任务实际成功 |
| P1 | 长会话、大历史和资源稳定性 | 形成并实测性能及资源预算，不预填尚未测量的数字 |

默认 CI 使用本地夹具；真实模型及外部服务验证独立、显式启用并记录实际范围。签名证书、商店账号和服务部署需届时确认，写入路线图不代表可以自行采购或发布。

## 候选扩展与范围取舍

复杂流程图节点、模板库、并行 worktree、更多执行器、Responses 协议、外部历史导入与跨项目长期任务继续保留为候选需求。实施前需说明具体使用场景、执行语义和兼容策略，不能只增加界面入口。

优先级冲突时，先保证日常主 Agent 的连续对话、实际编码、验证、停止与恢复，再增加编排复杂度。任何版本不得用远程或移动端开发替代已有桌面与纯接口能力的维护。

## 交付与文档同步

每版开始前确认范围并补充对应迭代计划；新增协议在实现时写入下一份协议文档，避免提前把设计写成已支持接口。每次交付更新 README、实施状态、相关协议和接手记录，给出提交、验证范围与残留问题。

近期接手以 [0.7 交接记录](handoff-v0.7.md) 为入口。用户委托下一个 Agent 后，由其执行开发；本次提交仅整理规划和交接。
