# Harness Agent 产品与架构计划

更新日期：2026-10-23

## 1. 产品目标与既定选择

构建本地优先的个人 Agent 工作台。用户通过桌面、后续通讯工具以及移动端管理同一套本地会话，通过自然语言生成计划图，再手动编辑或让 AI 调整后续步骤。

核心闭环是：输入目标 → 主 Agent 编排 → 子 Agent 执行 → 验证与修复 → 交付与回传。主 Agent 在子任务执行期间继续接收、管理和分配其他请求。

既定选择：

- 支持 macOS、Windows、Linux，使用 Tauri 2、React、TypeScript、Vite、shadcn/ui、Tailwind CSS 与 React Flow。
- Rust 独立 daemon 负责调度、执行、权限、存储和恢复；桌面关闭后继续运行。
- Tokio、Axum、reqwest、serde、SQLite 作为后端基础；首版采用单机架构，不引入外部消息队列。
- 同时提供自建模型工具循环和 Codex 执行器；Codex 先通过 app-server 的 stdio 协议适配。
- 模型支持自定义 Base URL、凭据、模型名，显式选择 Chat Completions 或 Responses 协议。
- 能力目录包含内置文件、搜索、补丁、命令、Git、检查工具，以及 MCP、本地 Skills、subagent 定义。
- 用户按任务授予权限，范围内自主执行；默认最多 10 轮实现与验证、2 小时、2 个工作节点并发，启动前可调整。
- 同一工作目录实行单写锁，已有改动纳入任务起始基线。权限兼容的只读节点可并行。
- 编排图按任务和角色组织，工具调用保留在节点详情。只有未开始节点可修改，已执行记录保持不变。
- 桌面 UI 参考 Codex 的工作台方向，以会话导航、主对话和按需展开的工作面板组织信息；通过自有组件实现，并融入编排、异步子任务和远程回传能力。

首版的本地会话指本应用管理的 Harness 会话及其关联执行器会话。导入其他应用的历史会话作为后续适配能力，不默认接管其他应用的全部会话。

### 桌面 UI：参考 Codex 的会话工作台

界面默认以主 Agent 对话为中心。用户提出目标、查看派发摘要、补充要求和接收结果；需要检查或修改编排时，再打开计划图。以下为本产品的具体布局约定，视觉细节在界面原型阶段确认。

| 区域 | 内容与交互 |
| --- | --- |
| 左侧导航 | 新建会话、按项目分组的会话列表、运行与待处理标记；底部放能力、远程连接和设置入口 |
| 会话顶部 | 会话名称、项目上下文和后台连接状态；运行中的任务显示简洁状态入口 |
| 中央对话 | 用户消息、主 Agent 回复、计划摘要、子任务卡片、验收结果与产物入口 |
| 底部输入区 | 多行输入、附件与上下文引用、模型选择；任务权限和预算通过次级菜单查看与设置 |
| 右侧工作面板 | 按需打开计划、更改、产物或选中任务详情，支持调整宽度与关闭 |
| 底部执行面板 | 按需打开命令输出、测试结果和事件详情，默认收起 |

主对话采用较克制的内容宽度和充分留白。左侧导航初始宽度 260px，可调整至 220–360px；对话阅读区最大宽度约 880px；右侧面板初始宽度 440px。窗口变窄时优先保留对话和输入区，侧面板改为覆盖式抽屉，导航可以折叠。

计划图在右侧面板中快速查看，可展开为主工作区编辑，并保留切回对话的入口。修改使用与 AI 相同的 PlanPatch；图中明确区分已完成、执行中、待开始与等待输入节点。

子任务以紧凑卡片出现在对话中，展示角色、任务摘要、当前状态、耗时和结果入口。展开卡片后查看其上下文、执行记录和产物。切换到子任务详情只改变查看对象，输入框继续面向主 Agent；向子任务补充指令使用卡片内的显式操作，并显示目标。

非阻塞交互要求：

- 子任务运行期间，主 Agent 输入框保持可用；新指令显示已接收、待处理或已处理状态。
- 停止生成、暂停后续调度、中断当前节点和取消任务使用不同名称与明确的作用对象。
- 会话列表持续显示后台任务状态；切换会话不取消任务，不自动切换执行焦点。
- 完成事件更新对应卡片和会话标记，不强制跳转会话或打断当前输入。
- 每条跨入口消息可查看来源；任务详情展示回传目标和投递状态。
- 需要回答的问题集中标记为待处理，点击后定位所属会话和任务。

视觉采用中性色底、细分割线、低对比层级和少量状态色，同时提供明暗主题。沿用 shadcn/ui 的交互基础，以统一的设计 token 管理字体、间距、圆角和颜色。状态除颜色外同时使用文字或图标表达，主要操作支持键盘和可见焦点。

设置页分别管理模型、subagent、MCP、Skills、权限、后台服务与远程连接。远程入口页展示身份绑定、入口选中会话和投递记录；桌面会话的选择与远程入口的选择分别显示。

## 2. 统一入口与本地会话管理

### 输入与输出分层

所有入口共用相同的应用服务和权限检查：

```text
桌面 / 通讯工具 / H5 / App
          ↓
ChannelAdapter → 身份与会话路由 → Command Inbox
                                      ↓
                              Main Agent / 控制命令
                                      ↓
                              持久化任务与执行事件
                                      ↓
                   桌面事件订阅 / 可靠回传队列 → ChannelAdapter
```

ChannelAdapter 只负责平台协议转换、身份凭据验证、消息接收与结果投递。任务策略、会话历史、计划图、权限和业务状态集中在 Rust 内核。

预留 HTTP 接收、出站长连接、轮询三种传输形态。具体通讯工具尚未指定，首版通过模拟 ChannelAdapter 验证完整链路，不绑定某个平台的数据格式。

### 身份、会话和任务的关系

| 对象 | 含义 |
| --- | --- |
| Principal | 已配对、获授权的操作身份 |
| ChannelBinding | 入口账户、外部对话、话题及发送人到本地身份的映射 |
| Session | 用户可以选择和继续回复的本地会话 |
| SessionSelection | 某身份在某通讯上下文中当前选中的本地会话 |
| TaskRun | 会话下的一次目标执行 |
| DelegationTask | 主 Agent 显式派给子 Agent 的可追踪任务 |
| ExecutorSessionRef | 关联 Codex 等执行器内部的会话标识 |
| ReplyTarget | 一次请求或任务保存的回传位置 |
| PendingInput | 需要用户回答的问题及其所属会话和任务 |

切换会话只改变后续普通消息的路由，不迁移任务、不取消任务，也不改变旧任务的 ReplyTarget。

SessionSelection 按入口、账户、外部对话、话题和操作身份分开保存；桌面与各远程入口可以选中不同会话。共享群聊中的会话选择不会相互覆盖。

### 指令协议

统一 CommandEnvelope 至少包含：

- 协议版本、command_id、入口标识和入口事件唯一标识。
- 已验证的 principal_id 及外部会话上下文。
- 可选 session_id、task_id、reply_to_event_id。
- 指令类型与结构化载荷。
- reply_target、关联请求标识和接收时间。

命令协议支持：

- 列出、新建、查看与选择会话。
- 向指定或当前会话发送消息、启动任务。
- 查看状态、计划、结果与产物。
- 修改未来计划、暂停后续调度、中断当前执行、取消或恢复任务。
- 回答特定 PendingInput。

结构化控制命令直接进入应用服务；自然语言交给主 Agent 理解，最终仍调用相同的类型化命令。

路由优先级固定为：已验证的消息回复关联 → 显式 session_id → 当前入口的 SessionSelection。两项显式关联互相冲突时拒绝并提示。没有有效选择时返回可访问会话列表或新建会话操作，不猜测目标。

通讯平台中的账号或会话标识必须先绑定到 Principal，不能直接取得本地控制权限。远程权限受身份授权与任务授权共同约束；新增权限通过桌面或已授权的安全管理入口设置，模型输出不能自行提升权限。

### 接收确认与幂等

输入先进入 SQLite 的 Command Inbox，再返回 accepted 和 command_id；已派发任务的确认附带 task_id。接收确认不表示执行成功。

通过入口、账户和外部事件 ID 去重；普通 API 客户端使用 command_id。重复投递返回已有处理结果，不重复派发子任务。

会话列表和状态查询不依赖模型调用。输入队列与工作队列均设容量限制，超限时明确返回繁忙状态，不静默丢弃。

## 3. 非阻塞主 Agent 与执行模型

### 主 Agent 是逻辑统一的管理者

主 Agent 负责理解请求、管理会话、生成和调整计划、发现能力、派发任务、处理结果及协调后续工作。编码、长命令、测试和修复循环交给子 Agent 或执行节点。

分配任务时，将 DelegationTask 与待执行记录持久化，返回 task_id 和初始状态。主 Agent 的本次决策随即结束，不等待子任务完成。

Rust 实现采用按会话组织的消息处理与异步工作任务：

- 同一会话的状态修改、计划变更与决策提交有序执行。
- 不同会话独立调度；某会话的模型调用不占住全局入口。
- 不在持有会话锁时等待模型、工具、命令或子任务。
- 同一会话同时只提交一个主 Agent 决策，避免并发改写对话历史。
- 模型请求异步执行；新输入先确认接收，进入短决策队列。暂停、取消、查询等控制操作独立处理，不等模型响应。
- 主 Agent 决策只允许有时限的控制操作，工具实现不得让其等待工作节点完成。
- 协调器和工作节点使用独立并发配额，为协调器保留请求容量；模型提供商的整体限流仍正常处理。
- 队列与完成事件持久化；进程内 channel 只用于唤醒和传输，不作为唯一事实来源。

“子任务异步运行”和“主 Agent 在同一会话连续回复”分开实现：执行器等待不会阻塞接收，模型推理也不会锁住状态查询、取消和其他会话。

### 计划与执行保持一致

节点类型包括 Agent、Command / Check、Condition、Loop、Human。依赖决定顺序和并行，循环使用显式 Loop 节点。

手动编辑与 AI 修改均提交带版本的 PlanPatch，检查依赖、能力、权限和节点状态。只有尚未开始的节点可以修改，重试创建新的 NodeAttempt。

子任务完成后生成结构化结果，包括状态、结论、产物引用、验收证据和下一步建议。父任务是否完成由计划依赖和验收标准决定，单个子任务完成不等于整个目标完成。

### 上下文交接

subagent 接收任务目标、相关项目规则、所需摘要与产物引用，避免复制整个会话。能力目录向主 Agent 和允许编排的 subagent 提供统一发现接口。

Skills 和历史记录提供参考，不产生额外权限。执行器能力在注册时声明，不能支持所需约束时，任务启动前返回明确的兼容性问题。

## 4. 子任务回调与可靠投递

### 内部结果与外部回传两条支路

子任务进入终态时，在同一数据库事务中：

1. 更新子任务状态与结果引用。
2. 保存对应 RunEvent。
3. 写入发往主 Agent 的完成消息。
4. 为已登记回传目标写入 Outbox 投递记录。

随后独立的协调器继续处理依赖，Delivery Worker 执行外部投递。通讯工具回传不需要等主 Agent 再调用一次模型，也不等待父任务整体结束。

默认回传内容来自结构化结果模板，包含会话、任务标识、状态、摘要、验收情况和可用产物操作。模型生成的润色是可选项，不影响基础通知。

### 回传策略

- 远程显式派发的可追踪子任务，默认订阅 completed、failed、cancelled、input_required。
- 自动产生的内部节点与逐次工具调用不逐条通知；需要时可显式订阅。
- 连续进度推送默认关闭，可按任务开启。
- ReplyTarget 在派发时保存入口、账户、外部对话、话题和关联消息，不引用后来变化的 SessionSelection。
- 回复旧任务的通知或待回答问题，按原 task_id / question_id 路由，并重新校验身份权限。
- 默认回传原始位置；需要跨入口通知时，必须事先配置可访问的额外目标。
- 消息长度、线程回复、卡片和附件由适配器按能力呈现；不支持时退化为文本与可用操作。
- 默认不发送完整日志、凭据或本机绝对文件路径；产物通过授权的获取接口或渠道附件能力提供。

### 投递状态与恢复

任务执行状态和 Delivery 状态独立。任务完成后，外部消息发送失败不会把任务改成失败，也不会阻塞主 Agent。

Outbox 采用待发送、发送中、已发送、等待重试、失败待处理等状态。使用持久化租约领取，按目标顺序投递，指数退避重试；超过上限进入失败列表，可手动重试。

投递以至少一次尝试为基础，通过 event_id、目标和平台幂等能力尽量去重。外部平台不支持幂等且发送超时的场景，保留“结果未知”记录；不承诺跨平台恰好一次送达。

所有输出经过同一投递服务，完成通知、主 Agent 即时回复、接收确认和待回答问题都可以追踪。渠道撤权或取消绑定后，停止向该目标继续发送。

## 5. 进程、接口与后续远程部署

### 组件边界

| 组件 | 职责 |
| --- | --- |
| ChannelAdapter | 身份验证、接收外部事件、解析命令、呈现和发送消息 |
| SessionRouter | 身份授权、会话目录、选择与回复关联 |
| CommandService | 类型化业务指令、幂等接收及应用状态修改 |
| MainAgentCoordinator | 有序决策、计划调整、任务分配和结果处理 |
| TaskScheduler | 持久化调度、依赖、预算、并发和工作目录锁 |
| AgentExecutor | 自建 agent 与 Codex 的执行、取消、会话恢复和能力声明 |
| CapabilityRegistry | 工具、MCP、Skills 与 subagent 发现 |
| DeliveryService | Outbox、消息格式化、路由、重试和投递记录 |
| ArtifactStore | 产物保存、引用与授权获取 |

### 对外接口

首版提供带版本的本机接口：

- 查询与管理 sessions、tasks、capabilities 和 deliveries。
- 提交 commands，返回接收凭证与处理状态。
- 提交带版本的计划修改。
- 通过 SSE 订阅执行和投递事件，支持事件游标重连；历史超出保留范围时重新获取状态快照。

桌面通过 Tauri Rust 桥调用这些应用服务。未来 H5、App 和通讯适配器复用协议、身份与业务语义，前端组件按需复用，避免复制编排逻辑。

### 本机与远程访问分开

daemon 默认只监听本机并验证连接令牌。首版实现 ChannelAdapter 契约、模拟入口及本机调试链路，不开放公网控制端口。

后续通讯工具优先使用其支持的出站连接或轮询；必须接收公网 webhook 时，通过验证签名的网关转发。

H5 / App 阶段增加可选远程网关：本机 daemon 主动建立认证出站连接，移动端通过网关访问已配对设备。网关负责连接、认证和转发，本机继续保存并执行会话与任务。离线时返回设备不可用；网关不默认缓存可执行指令。

### 崩溃与故障恢复

保存接收命令、计划版本、NodeAttempt、执行器会话、结果和投递状态。桌面退出不影响后台。

daemon 重启后恢复未处理命令和未发送消息，并对运行中状态做核实。崩溃时结果未知的命令、Git 推送或外部写入不能直接重放。内部完成消息通过 event_id 去重，重复处理不能重复推进计划或派发下一轮任务。

## 6. 交付阶段与验收

### 阶段一：后台、会话与协议骨架

完成参考 Codex 工作台方向的桌面原型与三端骨架、独立 daemon、SQLite、凭据存储、Session / Task 类型、Command Inbox、身份与选择路由、事件订阅及模拟 ChannelAdapter。

验收：确认会话导航、对话、输入区和可折叠工作面板的布局；桌面和模拟远程入口管理同一份会话；重复输入不重复建任务，切换会话相互独立，关闭窗口后后台继续运行。

### 阶段二：非阻塞主 Agent 与自建执行闭环

完成主 Agent 消息处理、自建执行器、模型网关、基础工具、调度与预算、结构化结果，以及只读计划图。

验收：子任务执行长测试时，主 Agent 仍可接受新消息、列出会话、切换目标、派发其他任务和取消执行；验证失败后按预算自动修复。

### 阶段三：可靠回传与混合能力

完成 Outbox、Delivery Worker、任务通知、待回答问题、投递记录、Codex 执行器、MCP、Skills 和 subagent 配置。

验收：远程发起任务后立即收到接收确认；子任务完成直接回传原位置，且不依赖主 Agent 空闲。渠道离线与 daemon 重启后可恢复投递。模型、MCP 或执行器故障都产生可查询状态。

### 阶段四：自由编排与三端稳定性

完成图编辑、AI 动态改图、控制操作、子任务卡片、代码差异、命令输出、产物、远程回传视图、交接及安装包。

验收：手动和 AI 修改遵守相同规则；检查权限、单写锁、预算和恢复；验证明暗主题、窄窗口、键盘操作和执行中持续输入；三端验证安装、中文路径、命令中断、凭据和后台生命周期。

### 后续版本

- 接入一个实际通讯工具，验证签名、身份配对、线程回复、回调和权限管理。
- 实现可选远程网关与 H5，再评估独立 App；保持本机会话和主 Agent 逻辑一致。
- 按需求扩展其他执行器、外部历史会话导入、并行 worktree 与跨项目长期任务。

### 必测场景

1. 让一个子任务一直等待，验证同一会话仍能接收新输入，其他会话能派发任务，查询和取消不等待工作节点。
2. 主 Agent 模型响应挂起时，结构化控制命令照常处理，其他会话继续调度。
3. 在远程入口选择会话 A 并派发任务，再切换到 B，A 的结果仍标明 A 并回传原位置。
4. 两个入口、两名操作身份和不同群话题的 SessionSelection 互不覆盖。
5. 重复的输入事件、完成事件和重启恢复不会重复派发任务或推进计划。
6. 在“结果与 Outbox 提交后、发送前”杀掉 daemon，重启后能够继续投递。
7. 模拟发送超时、响应丢失、平台不支持幂等与渠道撤权，验证投递状态及处理策略。
8. 回复旧通知或 PendingInput 时，正确定位原会话与任务；显式关联冲突时不误路由。
9. 取消与完成并发时只产生一个有效终态及对应完成事件，并保留实际副作用证据。
10. 某子任务失败、某回调失败和某工作目录被占用，不阻塞主 Agent 管理其他会话。
11. 超权限远程请求被拒绝；单个节点完成不能把尚未验收的父任务标记成功。
12. 子任务运行时主输入区保持可用，打开子任务详情后补充消息仍正确发送给主 Agent；显式给子任务追加指令时显示目标。
13. 切换会话和接收完成通知不丢失输入草稿、不抢焦点；计划图展开后可以返回原对话位置。
14. 明暗主题、窄窗口和键盘导航下，运行、失败、等待输入与投递异常均可辨认和操作。

最终成功标准：在桌面或远程入口提出目标后，主 Agent 可以自主编排并持续接收管理指令；子 Agent 在后台完成编码与验证，结果准确回到所属会话和指定通讯位置。
