## 第二阶段：已实现

- 独立主智能体 worker，通过模型生成计划草稿、回复讨论消息并回顾子任务结果；接收指令不等待模型。
- SQLite 持久化 plans / coordinator_jobs，指令收据仍在事务内幂等保存。
- 草稿可编辑任务标题、完整目标和依赖；保存与启动使用 expected_revision；后端校验 DAG 和 1–12 个节点上限。
- 父计划与子任务关联，真实依赖控制排队，并把依赖结果传给后续任务。
- 子任务结束后只排一个回顾作业；支持完成、追加任务、等待输入，最多 3 轮、累计 12 个节点。
- 取消计划同时取消子任务与回顾作业，挂起的回顾请求可被中断，迟到结果不会恢复计划。
- 子任务与最终父任务使用最初来源的持久化回调；切换会话或从另一入口启动不会改写回传目标。
- 后台重启恢复主智能体请求；已开始的项目写入不重放，父计划继续推进至回顾／人工介入。
- 系统文案默认中文，已知旧版本固定英文模板在展示时映射为中文；用户与模型原文保留。
- 中性灰与蓝色明暗主题，替换绿色状态、图连线、favicon 和桌面图标。

## 第三阶段：已实现

- Codex app-server stdio 执行器，每个子任务创建临时会话，真实终态和最终消息决定任务成功。
- 最多 16 个可编辑角色，独立职责、执行器和模型；计划节点按角色分配。
- 用户目标入队时固化角色；草稿、依赖延迟派发、自动追加和历史任务保留各自快照。
- Codex 直接任务无需主 Agent 模型；规划与回顾仍使用兼容 Chat Completions 服务。
- Codex 执行器限定 workspace-write、禁止命令网络及额外临时目录写入；不支持的授权或交互请求拒绝后停止。
- 100ms 取消检查、回合中断及执行器进程树回收，15 分钟及有界协议输出。
- 已保存 Codex 路径的版本检测；不校验登录、不调用模型、不回显原始错误或凭据。
- 原生标题栏和工作区主题同步，启动及切换时保持灰蓝明暗配色；主题同步失败显示中文提示。
- 桌面桥接检查后台版本，避免新版 UI 静默连接旧版后台。

测试包含本地 Codex 协议夹具与混合执行器计划；本机 0.163.0 已完成初始化和会话探测。第四阶段进一步完成真实云端执行闭环。Codex fixture 目前只在 Unix 执行，Windows 的 HTTP 角色测试使用原生执行器。

Codex 当前每个任务新建会话，不恢复 thread，不提供审批界面。本机已配置的 MCP / Skills 可能由 Codex 加载，本应用尚不管理它们；不能据本机命令沙箱保证远端工具行为。阶段三协议见 `protocol-v2.md`。

## 第四阶段：已实现

- 暂停／恢复新任务派发；在途执行可完成，等项目锁的任务启动前再次检查暂停；取消负责停止执行器。

- 隔离项目真实 Codex 文件修改、测试失败、修复、复验与回调通过，同时验证暂停恢复、中途补充与取消。规划和回顾响应采用本地夹具，未验证真实主模型规划质量。

## 0.5.1 模型下拉选择

- 对话输入区直接下拉切换主智能体模型，选择后保存，后续请求使用新模型。
- 设置页根据当前填写的地址和密钥获取兼容服务的 `GET /models` 列表，支持刷新、自定义 ID；获取列表不保存设置，不自动替换已有选择。
- 原生执行角色使用同一服务列表，可继承主模型；Codex 角色通过本机 CLI 的 `model/list` 获取独立列表，支持分页、隐藏项过滤和本机默认模型。
- 新增认证接口 `POST /api/v1/models`，请求可包含 `base_url`、`api_key` 或 `executor: "codex"`；返回 `models: [{id, name}]`。Codex 使用已保存的 CLI 路径。
- 请求有时限和响应大小限制；变更服务地址不转发原地址的已保存密钥，不跟随重定向，不回显上游错误正文。列表失败时保留选择，允许手动填写；获取成功不代表每个模型均支持规划 JSON 或工具调用。
- 本机验证：44 项前端测试、4 项核心测试、72 项后台测试、2 项桌面桥接测试、模型发现与原生执行 HTTP 测试及 Clippy 通过；macOS 打包和原生下拉选择／保存通过。本机真实 Codex 返回 10 个模型，未创建任务或调用模型。

## 0.5.2 配置修复与本机服务复用

- 修正配置完整性判定：无效地址、空模型、疑似密钥不再显示为已配置；主模型和角色模型统一校验。旧设置中的疑似密钥从模型字段清除，不自动转存或发往其他服务。
- 增加 `provider_source: manual | local_codex`，旧数据默认 manual。local_codex 每次请求只读本机 Codex 顶层选中自定义服务，复用地址、模型、Bearer 和静态／环境请求头；用户可另选模型，凭据不复制到数据库或前端。
- 模型发现、主智能体和原生子任务共用来源与鉴权；不跟随重定向。输出与执行证据隐藏当前凭据和附加请求头值，解析错误不回显配置原文。
- 新增认证接口 `GET /api/v1/provider/local-codex` 返回公开元信息，`POST /api/v1/settings/check` 检测未保存草稿的 JSON 推理；最多 30 秒、256 KiB，不保存配置、不创建任务、不持有设置锁等待模型。
- 设置页提供来源选择、只读来源地址、模型下拉与真实连接检测；编辑草稿后不沿用旧检测结果。配置完整不等于连接已验证。
- local_codex 暂不合并 profile 或项目覆盖、不读取 auth.json、不支持专属登录；仍要求服务兼容 Chat Completions。手动密钥继续仅存内存，切换地址会清除旧服务密钥。
- 新增三平台 HTTP 回归，覆盖只读来源预览、检测不保存、附加请求头、模型发现、主模型回复、原生文件写入、结果脱敏和重启重读来源。
- 本机验证：44 项前端、4 项核心、78 项后台、2 项桌面测试及七组 HTTP 回归通过，格式与 Clippy 通过，macOS 打包成功。真实服务返回 11 个模型；真实主模型回复与原生 read_file 工具、JSON 检测、重启重读来源均通过。日常桌面已保存复用来源，原会话保留。

- 主任务持久化模型、执行器、上下文策略；同会话排队顺序执行，启动后带入前序对话及实际结果，过滤后续输入。

## 当前限制与后续开发

1. 远程编排的计划先形成草稿、人工启动；自然语言调整需要选择已有计划并确认应用。画布仍是 DAG，尚无条件分支、显式循环、人工确认节点和可复用模板库。
2. 验收命令质量由用户和规划者决定；当前只验证执行记录和依赖关系，尚无文件内容快照、修改后验收失效或节点级重跑。
3. MCP / Skills 的应用内管理、更完整的角色权限与执行预算配置。
4. 按任务的权限与预算配置、系统凭据存储、跨执行器的持久上下文摘要和 Codex thread 恢复。
5. 真实通讯平台适配器、身份配对与回调投递；当前只有本地模拟接收端。
6. 可选远程网关、H5 / App、正式签名分发及自动更新。

原生直接主智能体和子智能体采用非流式 Chat Completions 工具调用；远程规划与回顾要求 JSON 对象输出。本地确定性模型测试覆盖协议与工具执行，真实云端主模型与 Codex 已完成上述受控联合案例。

完整设计描述目标行为；第六阶段协议、第五阶段协议、运行控制协议、角色协议、基础编排协议和本文件描述当前可运行版本。未接通能力在界面标为未启用。
