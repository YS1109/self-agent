# 实施状态

更新日期：2026-10-23

当前版本：0.4.1。

## 已实现的 v0 边界

- Tauri 桌面外壳和 React 会话工作台。
- 本机 Rust daemon、令牌认证、SQLite 会话和执行记录。
- 持久化指令去重、后台任务、工作目录单写控制和任务取消。
- 非阻塞管理指令与执行进度展示。
- 原生 Chat Completions 工具循环，以及显式演示模式。
- 子任务终态与回传记录的事务保存、独立本地投递 worker。
- 桌面与模拟远程入口各自的会话选择和固定任务回传目标。
- 重启恢复策略、原生工具路径约束和端到端测试。

## 第二阶段：已实现

- 独立主智能体 worker，通过模型生成计划草稿、回复讨论消息并回顾子任务结果；接收指令不等待模型。
- SQLite 持久化 plans / coordinator_jobs，指令收据仍在事务内幂等保存。
- 草稿可编辑任务标题、完整目标和依赖；保存与启动使用 expected_revision；后端校验 DAG 和 1–12 个节点上限。
- 父计划与子任务关联，真实依赖控制排队，并把依赖结果传给后续任务。
- 子任务结束后只排一个回顾作业；支持完成、追加任务、等待输入，最多 3 轮、累计 12 个节点。
- 取消计划同时取消子任务与回顾作业，挂起的回顾请求可被中断，迟到结果不会恢复计划。
- 子任务与最终父任务使用最初来源的持久化回调；切换会话或从另一入口启动不会改写回传目标。
- 后台重启恢复主智能体请求；已开始的项目写入不重放，父计划继续推进至回顾／人工介入。
- 系统文案默认中文，已知旧版本固定英文模板在展示时映射为中文；用户与模型原文保留。
- 中性灰与蓝色明暗主题，替换绿色状态、图连线、favicon 和桌面图标。

## 第三阶段：已实现

- Codex app-server stdio 执行器，每个子任务创建临时会话，真实终态和最终消息决定任务成功。
- 最多 16 个可编辑角色，独立职责、执行器和模型；计划节点按角色分配。
- 用户目标入队时固化角色；草稿、依赖延迟派发、自动追加和历史任务保留各自快照。
- Codex 直接任务无需主 Agent 模型；规划与回顾仍使用兼容 Chat Completions 服务。
- Codex 执行器限定 workspace-write、禁止命令网络及额外临时目录写入；不支持的授权或交互请求拒绝后停止。
- 100ms 取消检查、回合中断及执行器进程树回收，15 分钟及有界协议输出。
- 已保存 Codex 路径的版本检测；不校验登录、不调用模型、不回显原始错误或凭据。
- 原生标题栏和工作区主题同步，启动及切换时保持灰蓝明暗配色；主题同步失败显示中文提示。
- 桌面桥接检查后台版本，避免新版 UI 静默连接旧版后台。

测试包含本地 Codex 协议夹具与混合执行器计划；本机 0.163.0 已完成初始化和会话探测。第四阶段进一步完成真实云端执行闭环。Codex fixture 目前只在 Unix 执行，Windows 的 HTTP 角色测试使用原生执行器。

Codex 当前每个任务新建会话，不恢复 thread，不提供审批界面。本机已配置的 MCP / Skills 可能由 Codex 加载，本应用尚不管理它们；不能据本机命令沙箱保证远端工具行为。阶段三协议见 `protocol-v2.md`。

## 第四阶段：已实现

- 运行中全图 PlanPatch，修改尚未开始的节点、角色和依赖，追加后续任务；版本冲突原子拒绝，保留本地编辑。
- 暂停／恢复新任务派发；在途执行可完成，等项目锁的任务启动前再次检查暂停；取消负责停止执行器。
- 迟到回顾失效，修改排队任务保留被替代历史，累计节点 ID 预算防止删除后绕过十二节点限制。
- 显式 repairs／verifies 关系，验收节点依赖对应修复；failed／blocked／cancelled 历史以 resolved_by 标记解决，不抹掉失败。
- Native 和 Codex 采集真实命令、退出码和有界输出，失败回合保留证据；指定命令最后一次执行成功才通过验收。
- 前端展示修复关系、验收命令和实际执行证据，中文灰蓝主题。
- 隔离项目真实 Codex 文件修改、测试失败、修复、复验与回调通过，同时验证暂停恢复、中途补充与取消。规划和回顾响应采用本地夹具，未验证真实主模型规划质量。

协议见 `protocol-v3.md`。新增运行控制 HTTP smoke 已纳入三平台 CI，云端 Codex 实测仅在本机 macOS 执行。

## 当前限制与后续开发

1. 计划先形成草稿、人工启动；聊天补充仍生成独立计划，当前通过计划面板结构化调整已有计划，尚无自然语言 PlanPatch。
2. 验收命令质量由用户和规划者决定；当前只验证执行记录和依赖关系，尚无文件内容快照、修改后验收失效或节点级重跑。
3. MCP / Skills 的应用内管理、更完整的角色权限与执行预算配置。
4. 按任务的权限与预算配置、系统凭据存储、完善的主 Agent 上下文交接。
5. 真实通讯平台适配器、身份配对与回调投递；当前只有本地模拟接收端。
6. 可选远程网关、H5 / App、正式签名分发及自动更新。

主智能体与原生执行器采用非流式 Chat Completions；主智能体要求 JSON 对象输出，原生子任务要求工具调用支持。没有使用真实云端主模型验证规划质量；本地确定性模型测试覆盖协议与工具执行，Codex 子执行器另外通过真实云端模型闭环。

完整设计描述目标行为；第四阶段协议、角色协议、基础编排协议和本文件描述当前可运行版本。未接通能力在界面标为未启用。
